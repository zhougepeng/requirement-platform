# 当前实施状态

## 当前方案：小团队单服务版

- 一个 Next.js/Node.js 服务，默认将业务数据、原始 Demo 工件和已发布 Demo 保存到本机数据目录。
- 读者登录后查看项目、PRD、Demo、版本和版本评论；Demo 在 iframe 沙箱中预览。
- 产品经理通过网页 API 上传 Demo ZIP 并发布新版本；历史版本与 Demo 目录不可覆盖。
- MCP `/mcp` 使用独立 `MCP_API_TOKEN`，可查询、评论和发布，适合受控自动化发布。
- 外网模式设为 `AUTH_MODE=feishu` 后，所有网页与 API 都需要飞书登录；员工是否可使用由本机员工目录控制，只有 `FEISHU_PUBLISHER_OPEN_IDS` 白名单中的启用员工可上传和发布。
- 管理员可通过“员工与权限”同步飞书组织架构、启用/停用员工和设置管理员；`FEISHU_ADMIN_OPEN_IDS` 是可选的启动兜底，没有配置时首个成功登录且当前没有启用管理员的账号自动成为管理员。
- AI 助手为可选能力，只读取当前版本的 PRD；未配置模型时明确返回“尚未配置”。

## 不再作为默认依赖

PostgreSQL、Redis、MinIO、Outline、Keycloak 和 Docker 全栈编排已停用并备份，不会随本机启动。备份位于：

- `archive/server-extensions-20260825/`：数据库、对象存储、Outline 与 Keycloak 代码。
- `deploy/archive/full-stack-20260825/`：实验性 Compose 编排。

它们仅在团队规模、并发写入或知识库协作有明确需求时重新评估。

## 已验证

1. Demo ZIP 上传、发布、历史版本回读、版本评论和不可变 Demo 目录的本机回归。
2. MCP 未携带令牌返回 401；携带令牌可列出项目、版本、评论和发布工具。
3. 飞书模式下，无登录会话的 API 返回 401；有效签名会话可读取数据。
4. 产品构建与代码检查通过。

## 外网部署前的必要配置

1. 准备 HTTPS 域名，并把 `<域名>/auth/callback` 配入飞书网页应用的重定向地址。
2. 服务器 `.env.local` 设置 `AUTH_MODE=feishu`、飞书 App ID/Secret、会话密钥、租户白名单、产品经理 Open ID 白名单和 MCP 令牌；`FEISHU_ADMIN_OPEN_IDS` 可选，仅用于指定启动管理员。
3. 将数据目录放在代码目录之外，并纳入每日备份；同一时间只运行一个平台进程。
4. 通过 IIS 或 Caddy 将 HTTPS 流量反向代理到本机 `127.0.0.1` 服务。

飞书首次登录后，访问 `/api/v1/auth/me` 可读取当前登录账号自己的 `openId`、启用状态和管理员状态；管理员需要先在飞书开放平台申请通讯录读取权限，再在页面同步员工目录。开发模式默认使用本地管理员身份，左侧底部可打开设置并进入员工权限和模型管理；页面用户菜单也提供飞书登录入口。
